# 滚轮方向的硬件动作

按键页可分别编辑滚轮向下和向上。
两方向使用当前配置中的两个动作记录，不使用按下和释放记录。
可选择鼠标键、键盘键、多媒体键、硬件功能、射击切换、宏、主机动作或禁用。
键盘可组合八个左右修饰键，“快捷操作”还提供办公组合及双击、三击预设。
主机动作可把竖直滚轮转换为左右滚动，也可执行当前 KDE 桌面的全部最小化。
“恢复此方向滚动”会恢复该方向原来的滚轮指令。

## 原程序依据

EXE `00619b60` 在普通按键之后构建两个滚轮记录。
记录来源为配置对象的 `b04` 和 `b78` 偏移。
它把目标记录的 `+4` 设为 1，再调用赋值转换器 `0062f6c8`。
固件 `06bd..06c6` 读取表头第 8 字，并按方向选择单个动作。

转换器的模式 1 将键盘释放动作追加到按下程序，并插入 `Delay 16 ms`。
该字符串位于 `014e195d`。`014e1969` 为 `MacroEnding`。
Consumer 和鼠标分支也把两个阶段放在同一程序中。
这些分支没有加入键盘使用的 16 ms 间隔。

Rust 编辑器遵循此布局。
键盘 A 的完整程序为 `2104 2810 2004 262f`。
左键点击为 `2501 2401 262f`。
播放/暂停为 `34cd 30cd 262f`。
只需单个指令的 DPI、配置和灯光动作继续保存为直接动作。
需要按住的精确模式不显示在滚轮菜单中。

## 自定义宏

`macros::compile_wheel` 以单次模式编译奥斯卡II的按下和释放文本。
它用释放程序替换按下程序末尾的 END。
两段保留各自的相对跳转和源代码行号。
跳到按下程序末尾时进入释放程序。
按住和开关重复选项不用于滚轮。界面会显示此规则。
这不修改原宏草稿，普通按键继续使用原重复设置。

## 检查

2026-10-21，独立预期字检查覆盖鼠标点击、普通键、Ctrl、多媒体和配置切换。
测试还确认滚轮不提供按住功能，普通按键仍保留两个独立阶段。
宏检查覆盖两段中的相对跳转、按下末尾跳转、空程序和无效释放文本。
常规测试和 Clippy 检查通过。

这些是编码和编辑器检查。新滚轮映射的实体滚动效果尚未实机验证。
不应把保存器的既有实机结果当作这些新映射的执行证据。

cargo test --locked --bin bloody_a90 app::keys::tests::wheel_hardware_assignments_include_release_edges_and_keep_button_behavior
