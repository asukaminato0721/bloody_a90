# 按键和滚轮的主机动作

当前实现使用固件 07 的厂商状态通知。
打开目标、文字、缩放和窗口动作不接管物理输入设备。
指定两套手势时，服务与普通触发键共用一个物理鼠标读取器。
通知报文的证据见 [VENDOR-INPUT.md](VENDOR-INPUT.md)。

## 使用方法

1. 连接鼠标，在“按键”页选择配置和按键。
2. 选择“主机动作”。选择打开目标、文字、缩放、窗口动作、左右滚轮或手势。
3. 填写内容，点击“设定此按键”。
4. 点击“应用”。程序先检查动作和桌面接口，再保存文件和硬件表。
5. 保存成功后，程序启用主机动作服务。

界面创建的动作在按下时执行一次。滚轮动作在每一格通知到达时执行一次。
手势在按住时绘图，按所选的即时或释放模式执行。
两套手势可指定给顶端“1 / C / 3”键，并按配置分别设置。
点击“设定此按键”时载入手势页中的方向动作。之后修改方向需在手势页重新应用。
单独保存其他按键不会用手势页草稿替换已保存的方向表。
滚轮不能指定为手势触发键。
按键页可分别选择滚轮向下和向上。
“恢复此方向滚动”会恢复该方向的硬件滚动动作。
主机动作需要本程序保持运行。
“停止主机动作”会停止服务，并保存关闭状态。
再次启用使用已保存的动作，未应用的编辑仍保留在草稿中。

打开目标支持独立参数，每行一个参数，不经过 shell。
截图、桌面画笔和语音可通过此动作调用用户选择的 Linux 应用。
文字和窗口动作使用现有 KDE Wayland 后端。
缩放使用 Ctrl 配合一格滚轮。
“全部最小化”处理当前 KDE 桌面和活动的窗口。其他桌面的窗口保持原状态。
左右滚轮动作在按下时或每格滚动时执行一格，释放不会再滚动。
方向使用 `Simulator=9, Object=9, Action=5/6` 保存，这两个 Action 值代表左右方向。

## 保存与检查

`~/.config/bloody-a90/host-buttons.xml` 保存主机动作。
设置目录遵守 `XDG_CONFIG_HOME`。
文件包含每个配置的 24 个按键记录、两个滚轮记录、服务开关和对应硬件表的 16 字头部。
按键手势还保存两套完整方向表和单独的手势运行开关。
“应用全局设置”会更新这两套方向表，并合并普通触发键。
“停止全局手势”会停止两种手势触发方式。其他主机动作可以继续运行。
重新连接会恢复已保存的运行开关。
存在主机动作的硬件记录必须为直接空操作，防止硬件和主机同时产生动作。

保存前会执行以下检查：

- 编辑器最后读取的主机动作文件仍与磁盘一致。
- 每个主机动作对应的硬件记录都是空操作。
- 启用的动作可以编译，所需桌面接口可用。
- 新按键表的长度、校验和及配置数量符合保存要求。

文件保存失败时，不开始硬件保存。
硬件保存失败时，程序尝试恢复原文件字节。
如果原文件不存在，程序保存空的关闭状态。
恢复前会再次检查文件，发现其他修改时报告冲突。
硬件保存失败后不自动启动服务。

其他页面保存按键表时，会保留仍对应空操作的主机动作，并更新表头签名。
硬件动作替换同一记录时，程序移除该记录的主机动作。
旧文件与当前硬件表不一致时，普通硬件编辑不会沿用旧的主机动作。

含主机动作的配置导出为 `A90CFG` 版本 2。
该格式在原硬件数据后追加 XML 字节长度和主机动作。
导入会检查附件长度、签名及硬件空操作记录。
导入本身不启动动作，也不写入鼠标。
版本 1 继续可用，导入时不附带主机动作。

## 运行与清理

服务启用前会检查实际保存表中的记录，不只比较文件签名。
每个用户在同一个 hidraw 接口上只能运行一个本工具的主机动作服务。
独占标识使用 Linux 抽象 Unix 套接字，不创建锁文件。
厂商通知使用独立只读句柄。普通特征请求继续使用短期独占锁。

通知线程不执行特征查询。
另一个线程定期检查保存表头和通知模式。
发现表头改变或通知模式关闭时，服务停止并报告错误。
配置切换会清空待执行动作，释放本服务生成的按键，并采用新配置的动作。
启动或切换配置时已按住的键不算新按下，其首次释放也不触发动作。

停止服务时，程序先释放生成的按键，再等待后台检查和桌面服务结束。
有手势读取器时，程序先释放物理鼠标，再等待 HID 检查和通知模式恢复。
即使设置文件损坏或目标应用消失，停止全局手势也先释放鼠标。
最后恢复通知模式，释放套接字和文件句柄。
全局“中断宏”也会取消本服务尚未执行的动作。
固件中断路径可能清除通知模式。通过界面中断时，工作线程会在硬件中断后重新连接已启用的主机动作服务。
普通宏和全局手势继续使用已有的停止方法。

## 原程序的执行阶段

EXE `0045cd4c` 的 `20/21/22/24` 分支对应打开目标、文字、缩放和窗口操作。
`Action=0/1` 在按下阶段执行，`Action=3` 在两个按键阶段都执行。
`Action=2` 不执行这些主机操作。
`host_program::prepare_button` 按此规则准备普通按键动作。
界面使用 `Action=0`，防止一次点击启动两次目标。
全局手势继续使用原来的释放结果阶段。

EXE `0045cd4c` 的 `Simulator=2` 使用 `Object=0/1` 选择两套手势。
阶段 1 开始跟踪，阶段 2 结束跟踪。此分支不检查 `Action`。
原生通知和 evdev 来自不同端点，没有共同的帧时间戳。
松键通知会等待读完已到达的移动事件，再结束手势。
一个未读移动批次内存在多个触发过程时，程序取消不明确的笔画。
程序不会把内部触发键编号发送到桌面，也不会为原生空操作生成点击。

## 检查结果

2026-10-21，以下检查通过：

- 文件保留配置、中文、表情符号、换行和独立参数。非空硬件记录和无效附件被拒绝。
- 文件外部修改、硬件写入失败及读回失败的注入检查通过。失败恢复保留原文件，冲突恢复保留外部修改。
- 版本 2 的配置文件往返和版本 1 的兼容检查通过。
- 原生 egui 按键及滚轮编辑器可绘制。导入的主机动作在 DPI 刷新后继续保留。
- 隔离完整路径使用真实通知解析器、运行循环、uinput 和子进程。配置 1 的按键产生缩放，配置 2 的相同按键启动带独立参数的目标。
- 隔离路径确认 Ctrl 释放、中文及 `$()` 参数按原文传递、目标消失后错误上报，以及后续动作仍可执行。
- 隔离路径还在 Ctrl 持续按下时中断动作，确认按键释放且先前排队的通知不启动新动作。
- 实机服务启停、重复服务拒绝、同时执行特征查询、再次启用及通知模式恢复通过。测试使用没有对应物理按键的空记录，不生成输入。
- 实机检查模拟固件关闭通知模式，确认服务检测到变化并停止，随后可再次启动。
- 实机检查前后的完整闪存字节一致，运行配置也保持一致。
- 两套方向表、关闭状态、顶键指定、七个完整配置及版本 2 附件往返检查通过。
- 隔离原生手势完整路径覆盖三枚顶键、普通侧键、配置切换、方向动作、Ctrl 释放和紧急停止。两条路径共用同一个隔离输入源。
- 原生手势实机启停通过。测试只在无物理按键的空记录指定空方向表，不生成手势动作。停止后可重新独占物理鼠标。
