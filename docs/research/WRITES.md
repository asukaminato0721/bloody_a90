# 固件 07 的写入、擦除和危险命令

本文记录 2026-10-20 对固件 07 的静态分析和实机写入测试。
分析对象是 `a90-unlocked-flash-backup.bin`，SHA-256 为
`725528a1554745777b37e7ce8059080e622c55c7b7e0a38fbecae0b01924bf6c`。
Rust 读取器从鼠标重新读出的整片闪存与该备份逐字节相同。
反汇编使用 sn8dis 的 SN8F2288 指令集。地址均为字地址。

## 命令 2f 的写入路径

命令表从 `118e` 开始。命令 `2f` 经 `11c2` 跳到 `137a`。

1. `137a` 计算 `2400 - 地址` 和 `3e00 - 地址`。
   起始地址必须满足 `2400 ≤ 地址 ≤ 3e00`，否则直接返回。
2. 报告字节 2 的位 0 为 1 时进入写入路径 `1226`，否则进入读取路径。
3. `1226` 只在地址低字节为 `00` 且报告字节 5 的位 7 为 1 时调用 `123c`。
   `123c` 向 ISP 命令寄存器写入 `c3`，即擦除整页。
4. 随后写入 `5a`（页 `3f` 使用 `a5`），把报告中的字编程到闪存。

因此擦除单位是 256 个字。模式 `80` 只在页首擦除。
官方保存流程先把配置头写成 `ffff/ffff`，最后单独写入 `a4a4`，
不擦除即可从 `ffff` 编程为 `a4a4`。实机读回证实了这个顺序。

## 不能写入的区域

| 字地址 | 内容 | 依据 |
| --- | --- | --- |
| `0000` 至 `00ff` | 引导程序和复位向量。 | 复位后在 `0017` 检查字 `0100` 的低字节 `a4`。 |
| `3d00` 至 `3dff` | 位 7 命令（如 RAM 读 `81`）的处理程序。 | `118f` 在命令位 7 置位时跳到 `3d00`。 |
| `3e00` 至 `3eff` | 回报率、亮度等常规设置。 | 内存信息报告 `3e00`。固件经自身命令维护。 |
| `3f00` 至 `3fff` | 引导代码和设备数据。 | 复位路径调用 `3f00` 至 `3f17`。 |

按键区若一直写到 `3e00`，会在页首 `3d00` 擦除代码页。
旧 C 和 Python 实现允许主向量达到 `3000` 十六进制字节，这是错误的上限。
Rust 构建器和传输层把按键区限制在 `2600` 至 `3cff`，即最多 `1700` 个字。
灵敏度只写入 `2400` 页。`2500` 页不写入。

## BOOT HEAD 和 BOOT TAIL

`2400` 起有 `\x18\x22RIBOOT HEAD`，`2500` 起有 `BOOT TAIL`。
复位路径不读取这两处。固件只在 `117c` 读取 `2400` 的低字节，判断灵敏度保存表。
命令 `1e`（`1462`）会擦除 `0000` 页，并把 `2400` 页复制到 `0000`、
把 `2500` 页复制到 `3f00`。这两页是固件更新的暂存区。
当前内容只是占位文本。发送 `1e` 会用它覆盖引导程序。

官方程序保存灵敏度时会擦除 `2400` 页，覆盖 BOOT HEAD。
实机保存后鼠标正常工作，从备份恢复该页后也正常。

## 不得发送的命令

| 命令 | 原因 |
| --- | --- |
| `03` | 进入传感器串行传输，零计数会传输 256 次。疑为此前失去移动的原因。 |
| `1e` | 覆盖引导程序页 `0000` 和 `3f00`。 |
| `2a` | 写 `3ff3`，并在 `1419` 用 `2600` 页做暂存来重写 `3f00` 页。 |
| `25` 的错误魔数 | 设置 `44.4`，在复位前锁死该命令。 |

命令 `0d` 已单独通过运行值和移动事件检查，现用于即时应用 DPI 和回报率。
此前失去移动的测试也发送过命令 `03`。不能把此前失败直接归因于 `0d`。
完整证据见 [RUNTIME-SENSITIVITY.md](RUNTIME-SENSITIVITY.md)。

## 访问命令 20

`11da` 在 `41.6` 为零时把报告字节 7 的位 0 写入 `41.7`，并返回 `41.6`。
`41.7` 置位期间，`061e` 跳过配置重载，`197a` 跳过主循环的一部分。
官方流程先打开访问，写入后关闭。仅写闪存不会刷新运行时 DPI。
驱动保存灵敏度后发送命令 `0d`，再读回运行值和传感器更新状态。
保存回报率时只修改当前运行状态的回报率，保留当前 DPI 档位。

## 按键表的运行时配置序号

固件把当前配置序号保存在 RAM `263`，最大序号在 `264`。
出厂表头允许 7 个配置。出厂模式下 `080c` 强制查找配置 0，
但按键仍会让 `263` 在 0 至 6 之间循环，指示灯颜色随之变化。

保存表使用 `263` 直接索引配置指针列表。
第一次实机测试只写入 1 个配置，而鼠标正处于配置 6。
结果除移动外所有按键失效。从备份恢复按键页后立即恢复正常。

修正后的转换保留出厂表头的全部 7 个配置，共用按键表，
每个配置使用出厂元数据中自己的一对字。
传输层在保存按键表前读取 `263`，若它超出新表的配置数量则拒绝写入。
修正后的 487 字按键表实机测试正常。

`0a87` 至 `0ad2` 从所选表读取：

| 偏移 | RAM | 内容 |
| --- | --- | --- |

## 按键状态

RAM 第 2 页的 `5e`、`5f`、`60`（RAM 读地址 `025e` 至 `0260`）
分别保存按键 1 至 8、9 至 16、17 至 24 的按住状态。
`core_var` 读取这三个字节，`ifkey` 由此展开。
界面的按键查询以 RAM 读命令轮询这三个字节。

实机按键查询的结果：

| 物理按键 | 按键编号 | 出厂动作 |
| --- | --- | --- |
| 左、右、中、后侧、前侧 | 1 至 5 | 五个鼠标按键 |
| “1” | 9 | DPI 增加 |
| “C” | 10 | DPI 减少 |
| “3” | 11 | 配置循环，指示灯颜色随配置变化 |

按键编号 N 对应配置表中的第 N 条记录。

同一 hidraw 接口不能由两个进程同时访问。查询和响应会交错，响应头校验会失败。
当前 Rust 传输层在身份查询前取得独占 `flock`，并持有至设备句柄关闭。
锁保护本工具各线程和进程的完整操作，包含读取、修改和保存。
普通打开最多等待一秒。持续占用时返回错误，不发送 HID 请求。
手势宏通过独立读取线程取得物理按键状态，不阻塞 evdev 转发。
这些锁只协调使用相同锁机制的程序，不能协调其他厂商软件。

2026-10-20 的实机只读检查通过：

- 第一个句柄持有接口时，第二个驱动进程等待后报告占用。
- 第一个句柄随后仍可读取正确身份。
- 关闭第一个句柄后，新进程可读取完整设备信息。

检查命令为 `cargo test --locked --test device_access -- --ignored`。
本次检查没有保存配置，也没有写入闪存。

## 实机测试记录

每一步之后都读取运行时状态，并统计 `/dev/input/event5` 的移动事件。

1. 读取身份、内存信息、亮度和整片闪存。闪存与旧备份相同。
2. 亮度 3 → 2 → 3，读回一致。
3. 写入与出厂相同的灵敏度块，读回一致，移动正常。
4. 从备份恢复 `2400` 页，读回一致。
5. 写入 800/1600/3200 三档。拔插后 RAM `26` 变为 2，DPI 切换正常。
6. 写入 1 个配置的按键表，按键失效。恢复按键页后正常。原因见上文。
7. 写入 7 个配置的按键表，所有按键、DPI 切换和配置切换正常。
8. 按键查询确定物理按键编号，见上文。
9. 写入回报率 1000 Hz。拔插后 RAM `23` 为 1，evdev 时间戳的中位间隔为 1.00 ms。
10. 把“3”键设为键盘 A，键盘节点收到 `KEY_A`。
11. 把“3”键设为宏 `KeyDownUp 4`、`delay 50`、`KeyDownUp 5`，输入 ab。
12. 把“3”键设为 `gowhile` 和 `ifkey` 的宏，见下节。

## 弹起程序会中断按下程序

弹起动作是宏引用时，松开按键会启动弹起程序，并停止仍在运行的按下程序。
第一次测试把空的弹起程序存为只含 END 的宏，短按只输出一个 a。
出厂连击宏的弹起动作是直接动作 `262e`。
改为同样的直接空操作后，短按输出 aaab，按住输出 aaa，与程序语义一致。
`Action::from_program` 因此把空程序转换为直接空操作。

## 宏的中断

三种停止方式均在实机上验证，测试宏每 0.1 秒点一次 Shift：

| 方式 | 结果 |
| --- | --- |
| 按住重复，松开按键 | 按住约 2.5 秒输出 Shift，松开后停止。 |
| 开关重复，再按一次 | 第一次按下开始，约 7 秒后第二次按下停止。 |
| 键盘指示灯报告 `07` | 立即停止。 |

官方说明要求同时打开 Caps Lock、Scroll Lock、Num Lock 来中断宏。
固件 `1b0f` 在指示灯字节为 `07` 时停止宏。
`device::interrupt_macros` 向鼠标的键盘接口（接口 0）发送输出报告 `07`，
再按内核记录的指示灯状态恢复。界面的“中断宏”和命令 `--interrupt` 使用它。
`1b0f` 只有在 RAM `43.1` 置位时才重新载入配置表，
因此该报告不能用于即时应用新的 DPI。驱动使用命令 `0d` 完成此操作。

## 宏中的鼠标位移

7 位位移指令的处理程序 `0e53` 在 RAM `44.6` 置位时跳过位移。
`0621` 把设备数据字 `3ff3` 的低字节读入 `4e`。`4e.0` 为 1 且 `44.7` 为 0 时，
固件置位 `44.6`。本机 `3ff3` 为 `ffff`，因此宏中的位移不执行。
（此前记为 `2543` 有误，`2543` 位于 `3ffc`。2026-10-21 按闪存备份核对。）
命令 `2a`（`13ed`）在字节 2 位 0 为 0 时只读取 `3ff3`。为 1 时先核对密钥
（字节 8 为 `0f`，字节 12 至 15 为 `17 67 40 91`），通过后编程 `3ff3`；
写入值为 `ffff` 时改走 `1419`，用 `2600` 页暂存并重写 `3f00` 页。
实机测试中，开关重复的左右晃动宏没有产生任何移动事件，与此一致。
`3ff3` 由命令 `2a` 写入，属于官方的功能授权数据。本工具不写入它。
位移指令仍可编码和保存，在已授权的鼠标上应可执行。
