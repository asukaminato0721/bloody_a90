# 离线保存计划

`save_plan.py` 生成配置保存步骤和 64 字节报告。
模块不打开设备，不执行报告，也不启动官方程序。
当前 libratbag 驱动不引用此模块。

此模块补齐配置块编辑后的数据包描述。
它没有完成实机保存。
擦除范围、设备执行效果和完整配置布局仍需检查。

## 适用范围

输入必须符合以下条件：

- 型号掩码为 `04fc`，固件为 `07`。
- 输入是完整的已保存配置块，头部为 `a4a4/ffff`。
- 灵敏度块恰好为 256 字节。
- 按键块为 32 至 `3000` 十六进制字节，长度为偶数。
- 所有配置数据位于主向量内，没有外部存储向量。
- 调用者已检查指针、共享表和宏引用。

模块检查两个主向量校验值。
校验通过不能证明配置布局正确，也不能证明没有外部数据。
模块不会从出厂表构建完整配置。
现有出厂灵敏度表只有 54 个字，不能直接读取 256 字节作为模板。

地址来自此前取得的本机备份及内存信息：

| 配置 | 起始字地址 | 限制 |
| --- | --- | --- |
| 灵敏度 | `2400` | 本模块只描述 128 个字。 |
| 按键与宏 | `2600` | 补零后的末尾不得超过 `3e00`。 |

这些地址只适用于已分析的固件版本。

## 保存步骤

1. 轮询开启访问请求 `07 20 00 00 00 00 00 01`。
2. 每次查询成功后等待 3 ms，再检查响应的状态字节。
3. 状态字节为零时，再等待 3 ms。
4. 将配置头的前两个字暂时改为 `ffff/ffff`。
5. 每次描述 16 个字的写入，按字地址递增。
6. 最后一块不足 16 个字时补零。
7. 单独写入首字 `a4a4`，提交配置。
8. 轮询关闭访问请求 `07 20 00 00 00 00 00 00`。

开启和关闭请求的响应必须与请求的八字节头一致。
响应字节 8 为零时，轮询结束。
其余值均继续轮询。
官方函数没有为此循环设置次数限制。
本模块只描述这个条件，不实现循环或超时策略。

普通分块报告头为：

```text
07 2f 79 HH LL 80 00 00
```

`HH LL` 是字地址，采用高字节在前的顺序。
负载从字节 8 开始，采用小端字顺序。
头部字节 2 为 `(字数 - 1) * 8 + 1`。
16 个字对应 `79`，单字提交对应 `01`。
提交报告的头部字节 5 为零。

写入助手只发送 SET_FEATURE，不读取写入确认。
保存函数在分块或提交失败时调用关闭访问助手。
本模块描述成功路径。它不执行失败恢复。

## 静态证据

分析对象的 SHA-256：

```text
4a76f6ef4b6e7da699afbd8d3d780ae9747b599af795531a39e3eb5d93c93162
```

| EXE 地址 | 证据 |
| --- | --- |
| `0043c5d8` | 灵敏度块校验、八次分块写入、首字提交和关闭。 |
| `0043c7dd` | 调用开启助手。随后在 `0043c7e2` 传入 3 ms。 |
| `0043b1e8` | 按键保存。最后一块先清零，再复制剩余字。 |
| `005a0938` | 普通写入，字地址、计数字段和负载。 |
| `005a09f4` | 分块写入，头部字节 5 为 `80`。 |
| `005a1fa8` | 开启、关闭和状态轮询。 |
| `005a2049` | 每次查询成功后调用 `Sleep(3)`，包括状态为零的响应。 |
| `0059ee98` | 查询、读取响应、检查八字节头。末尾参数反向填入头部。 |
| `013ff176` | 跳转到导入表 `0164392c`。该项为 `KERNEL32.DLL!Sleep`。 |

固件 07 的对应入口：

- 命令 `20` 经 `11b3` 跳转至 `11da`。
  它读取报告字节 7 的位 0，并返回内部状态。
- 命令 `2f` 经 `11c2` 跳转至 `137a`。
  该入口检查配置地址范围，再区分读取和写入。
- 写入路径 `1226` 读取地址和模式字段。
  模式位参与调用 `123c` 的条件。
  `123c` 与 `1245` 使用不同的底层操作码序列。

模式 `80` 不能当作普通数据写入标志忽略。
准确的擦除范围仍需独立核对。
离线重建测试只模拟字替换，不模拟擦除。

完整官方保存流程还含即时灵敏度更新、旧式命令 `03`、
外部向量写入和保存后的主机操作。
本模块不描述这些操作。
其中命令 `03` 与固件 07 的含义不一致。
不能将官方 EXE 的调用序列直接用于这只鼠标。

## 使用和验证

```python
from save_plan import plan_main_only_save

plan = plan_main_only_save("buttons", complete_block, model=0x04fd, firmware=7)
```

`plan.steps` 含开启条件、分块报告、提交报告和关闭条件。
`plan.delay_after_open_ms` 是开启条件完成后的额外等待。
各轮询项的 `delay_after_response_ms` 是每次有效响应后的等待。
这些值记录官方程序行为，不表示实机时序通过验证。

```sh
python contrib/bloody-a90/test_save_plan.py
```

测试覆盖以下内容：

- 灵敏度示例的明确报告字节和八次分块。
- C 多配置编辑器生成的 512 字节配置。
- 最后一块补零，并排除补零对原校验值的影响。
- 字地址进位和配置区域末尾。
- 所有响应头字段、状态值、错误长度和损坏校验。
- 输入缓冲区不变，以及计划独立保存输入快照。

所有测试均使用内存和临时文件。
