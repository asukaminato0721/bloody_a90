# 手势：动作表和触发路径

本记录来自 2026-10-20 的静态分析。
对象与 [PROTOCOL.md](PROTOCOL.md) 中的 EXE 和固件相同。
手势文件编辑器和两套手势的局部识别预览已实现。
Linux 全局输入和主机执行已接入。验证范围和剩余限制见 [GESTURE-RUNTIME.md](GESTURE-RUNTIME.md)。
官方主机的识别与动作分派入口已经找到，见下文。

## 两套官方设置

undelphi 找到以下 VCL 窗口和事件。

| 窗口 | 方法 | 地址 |
| --- | --- | --- |
| `TformMouseGesturesDialog` | `FormCreate` | `004fb238` |
| 同上 | `FormShow` | `004fb66c` |
| 同上 | `bt_OKClick` | `004fcc94` |
| 同上 | `ck_RealTimeReplyClick` | `004fce20` |
| `TformMouseGesturesExDialog` | `FormCreate` | `004fd660` |
| 同上 | `FormShow` | `004fe7cc` |
| 同上 | `bt_OKClick` | `004ff1f0` |

第一套窗口使用 `16in1.gestures`。
文件包含 `Mode`、`Sensitivity` 和 16 个方向动作。
四个基本方向为上、下、左、右。
接下来是右上斜、左下斜、左上斜、右下斜。
最后八个是上左、上右、下左、下右、左上、左下、右上、右下的折线。
`FormShow` 从参数对象复制 16 个 `74` 字节的动作记录。
确认按钮保存实时响应开关和距离字段。
实时响应开关改变时，`004fc6dc` 控制后八个动作及距离控件是否可用。

第二套窗口使用 `Mouse.gestures`。
文件包含 `EnabledTipBoard` 和 16 个方向动作。
前四个方向相同。
接下来是上下、下上、右左、左右的折返。
最后八个是与第一套相同的折线。
界面资源包含四方向、八方向、十二方向的控件。
`FormShow` 也复制 16 个 `74` 字节的动作记录。
确认按钮保存提示窗口开关。

这些文件使用 UTF-8 BOM 和 XML 格式。
各动作包含 `Simulator`、`Object`、`Action`、宏名称、宏路径和显示文字等字段。
两套文件的默认动作不同。不能用同一组方向名称解释两个文件。
方向在文件中的顺序不等于已经证实的固件编号。

## 保存表

EXE 编译器 `00619b60` 为每个配置处理 162 个附加动作记录。
源地址为：

```text
全局 016127fc 指向的对象 + 配置序号 × 9ec8 + bec + 记录序号 × 74
```

每条记录经过 `0062f6c8`、`0060ed38` 和 `006112e0`。
162 条记录最终形成按下、弹起动作对。
主向量表头第 9 字指向这组表的配置指针列表。
相同的表可以共用存储。
现有 Rust 构建器和备份转换会保留保存表中的这些动作。
出厂表的相应指针指向代码，因此出厂转换使用完整空操作表。

162 可以分解为 9 × 18，但本次分析没有证明这种分组含义。
不能据此给记录分配方向。

## 主机识别和动作分派

`0045cd4c` 按动作记录的 Simulator 类型分派主机功能。
类型 `2`、Object `0` 使用 16 合一手势。Object `1` 使用普通鼠标手势。
按下时启动识别，弹起时停止识别并选择动作。
这些分支不在 `0062f6c8` 的普通设备宏转换路径中。

16 合一手势从 `0045ce65` 进入 `013eb4bc`，安装 Windows 低级鼠标钩子。
钩子函数 `013eaf0c` 处理 `WM_MOUSEMOVE`，调用 `013eaf80`。
`013eaf80` 累计位移，并使用 `013eb354` 判断方向。
它分别支持释放时识别和按距离即时响应两种状态。
初始化函数为 `013eb454` 和 `013eb494`。
释放处理函数 `013eb600` 移除钩子，再发送识别结果。

`013eb354` 返回 UTF-16 数字字符，坐标 Y 向下为正。
它先检查 `abs(X) < abs(Y / 2)`，再检查 `abs(Y) < abs(X / 2)`。
整数除法向零截断。其余非零象限使用斜向编码。

| 字符 | 方向 |
| --- | --- |
| `1` | 右 |
| `2` | 右上 |
| `3` | 上 |
| `4` | 左上 |
| `5` | 左 |
| `6` | 左下 |
| `7` | 下 |
| `8` | 右下 |
| `0` | 没有匹配方向 |

普通鼠标手势从 `0045d308` 进入 `013ec3b4`。
它创建提示窗口，并安装钩子 `013ec32c`。
该钩子把位置通过消息 `402` 发给窗口过程 `013ecb38`。
窗口调用 `013ef1a0` 过滤短距离移动并累计方向序列。
`013ef954` 使用角度常数 `-45`、`45`、`135` 和 `-135` 选择四个方向。
`013efa38` 匹配四个单方向及十二个双方向字符串。
字符串表为 `1`、`3`、`5`、`7`、`13`、`15`、`17`、`31`、`35`、`37`、
`51`、`53`、`57`、`71`、`73`、`75`。
停止函数 `013ec72c` 移除钩子，调用 `013f0650` 后关闭提示窗口。
角度生成函数 `013ef8a4` 使用带 X 轴符号的 `acos(-Y / distance)`。
它等价于从上方向顺时针计算方位角。
浮点数在精确斜线附近的取整行为仍需核对。
路径过滤和最终序列选择已经与汇编核对，见下文。

两套结果分别使用消息 `408` 和 `409`。
接收者为 `TtheTrig`，VMT 元数据地址 `01423aac`。
构造函数 `0046034c` 将窗口过程设为 `004611a4`。
消息处理把结果编码与 16 个动作的编号比较。
匹配后调用 `0045cd4c` 分派对应动作。
因此 Linux 实现需要主机端的输入跟踪、方向识别和动作分派。
仅保存主向量中的 162 对动作不能代替这条完整路径。
这 162 对动作与两套主机手势对象的对应关系尚未证实。

## Rust 实现范围

`src/gestures.rs` 读取 UTF-8 和带 BOM 的 UTF-16 文件。
写出格式为 UTF-8 BOM 和 CRLF，与官方文件相同。
解析器检查两套方向表、重复字段、整数、XML 节点数和文件长度。
解析器拒绝 DTD、命名空间和嵌套动作属性。
动作和根元素中的未知标量字段会保留。
文件中的注释、缩进和字段顺序不保留。

`src/app/gestures.rs` 提供“其他设置 → 手势”页面。
两套手势各自保留 16 个方向动作。
可设置键盘、媒体键、鼠标按键、上下滚轮和 AMC 宏路径。
还可设置左右滚轮和打开文件或程序。后者使用官方 `MacroName` 字段保存目标。
键盘 Object 按 `修饰键掩码 × 1000 + USB HID usage` 编码。
此公式来自 `0062f6c8` 的 Simulator 6 分支。
例如剪切为 `1027`，即左 Ctrl 和 usage 27。
只有点击替换按钮才会改变动作。
载入的其余动作继续保留，包括编辑器没有提供控件的类型。

`src/gesture_file.rs` 使用同目录临时文件完成写入。
替换前会比较载入时的原始字节。
另存为会拒绝已有名称。写入失败时不会截断原文件。
这些检查不能保证与另一个进程并发替换文件时的原子比较。
编辑草稿在关闭时保存，但文件的覆盖授权不会随草稿恢复。
重新启动后，需要载入原文件，或另存为一个新文件。

16 合一预览复现 `013eb354` 的八方向整数判断，以及释放模式的路径过滤。
累计位移长度必须大于 20，才产生一个方向样本。
第一个方向段保留。后续方向段需要三个相同样本，才能在下一次转向时保留。
该预览使用绘图区域中的屏幕位移，不执行动作。
普通手势预览复现 `013ef1a0` 的累计距离、样本加权和两轮过滤。
距离先向零取整。小于 10 时继续累计，10 至 30 产生一个样本，大于 30 产生 `距离 / 10` 个样本。
第一轮删除与两侧都不同的单个样本。
第二轮在连续三个样本相同时保留方向，并抑制连续的重复方向。
两轮都从索引 1 开始，在索引达到 `长度 - 1` 前停止。
字符串取片段和删除使用一基索引。取片段时，索引 0 会按 1 处理。
因此单方向至少需要五个样本，才能被第二轮保留。
这些行为来自 `0040f0c0`、`013c5360`、`013c50cc` 和 `008528f0`。
`013c4efc` 表示字符串不相等，底层 `00a9dbf4` 使用 `SETE` 实现相等检查。
`013bb69c` 临时设置 x87 的向零取整方式，不能按反编译中的普通 ROUND 处理。
Rust 使用几何四方向判断，精确斜线按分区边界处理。原程序的 x87 浮点误差可能改变边界结果。
预览限制每笔最多 8192 个方向样本。超出限制会使整笔手势无效。

全局输入跟踪、即时响应和 AMC 主机执行见 [GESTURE-RUNTIME.md](GESTURE-RUNTIME.md)。

三个语言目录中的六个官方文件均通过“读取 → 写出 → 再读”的语义一致检查。
测试还包含两套各 16 个释放路径、方向边界、错误文件、外部修改冲突和草稿恢复。

## 固件路径

固件主循环 `0647` 检查 RAM `0226` 的位 7，然后进入 `074d`。
`074d` 清除此位。RAM `003f` 的位 7 为一时直接返回。
条件允许时，`0755` 读取表头第 9 字，并经 `080c` 选择当前配置的表。
`075f` 至 `0760` 根据 RAM `0225` 和 `0226` 的状态选择动作偏移。
这些地址是字地址。

`0bea` 至 `0c22` 比较 RAM `0050` 起的 21 个字节与 RAM `0274` 起的状态。
它寻找改变的位，设置记录编号和按下或弹起标志，再置位 RAM `0226.7`。
这证明表的触发方式是状态位变化。它没有证明鼠标移动如何产生这些状态位。
`0a35` 还能把相应状态作为厂商报告子类型 `12` 发送给主机。

`0bb0` 和 `0bcd` 分别修改 RAM `0050` 起的位。
当前发现的直接入口只有 `0d7e` 和 `0d7f`，这两个入口没有已发现的直接调用者。
不能把这些函数当成已确认的 HID 命令，也不能据此认定功能不可用。
仍需检查主机的手势识别、间接调用和其他状态写入路径。
