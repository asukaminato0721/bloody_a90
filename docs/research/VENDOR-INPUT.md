# A90 厂商输入通知

此记录使用 PROTOCOL.md 中的 EXE 和固件 07。
`undelphi` 提取的 `TiomHidThreadId7M` 虚方法入口为 `0043dc38`。
该线程用独立句柄读取 HID 输入，按报文第二字节分发。
`0043e1b4` 解析子类型 `01`，再发送按键和滚轮的窗口消息。

## 启用与恢复

只打开 hidraw 输入句柄不会启用厂商通知。
固件 `0927..092e` 在 RAM `004b` 位 0 为零时清除普通状态通知标志。
首次实机检查未启用此位，因此没有收到通知。
该次检查恢复了运行配置。

| 操作 | EXE 入口 | 报文前缀 | 固件行为 |
| --- | --- | --- | --- |
| 启用通知 | `005a229c` | `07 09 00 00 00 00 00 00 01` | `119c -> 12de` 把字节 8 写入 RAM `004b`。 |
| 关闭通知 | `005a2318` | `07 09 00 00 00 00 00 00 00` | 同上。 |
| 请求当前状态 | `005a2394` | `07 06 00 00 00 00 00 00` | `1199 -> 1214` 置位通知待发送标志。 |

上述报文补零至 64 字节。命令不写闪存。
Rust 实现只修改 `004b` 的位 0，保留其他位。
`Session` 先创建恢复对象，再启用模式并请求初始状态。
正常结束会检查恢复结果。错误退出也会通过析构恢复。
进程被强制终止时，析构函数不能运行。

诊断会话在整个监听期间保留 `Device` 的特征请求独占锁。
同一会话仍可发送配置请求。其他进程的配置操作会按现有规则报告占用。
`Source` 使用另一个只读、非阻塞句柄读取输入，不发送特征请求，也不抢占输入设备。
每个句柄收到自身的输入副本。
读取器限制单批读取数量，避免通知持续到达时阻止调用方处理停止请求。
hidraw 没有为此报文提供可用的丢包计数。本实现不能证明没有丢失快速按键变化。

## 固件 07 的状态报文

固件 `09f1..0a34` 构造 64 字节报告。偏移包括报告 ID。

| 偏移 | 含义 | 固件依据 |
| --- | --- | --- |
| `0` | 报告 ID `07`。 | `09f3..09f4`。 |
| `1` | 子类型 `01`。 | `09f5..09f6`。 |
| `2` 高四位 | `1` 为滚轮向上，`f` 为向下，其他值不产生滚轮事件。 | `09f7..09fe`，EXE `0043e1b4`。 |
| `3..5` | 24 个物理按键状态，低位对应较小编号。 | RAM `025e..0260`。 |
| `7` 低三位 | 当前配置序号，从零开始。 | `0a0b..0a0d`，RAM `0263`。 |
| `12` 低三位 | 当前 DPI 档位，从零开始。 | `0a17..0a23`，RAM `0027`。 |
| `13` 低四位 | 射击状态字段，不是配置序号。 | `0a27..0a2b`，RAM `002f`。 |
| `14..15` | 此固件写入零。 | `0a2d..0a31`。 |

读取器忽略其他报告 ID 和子类型。
键盘报告、子类型 `12` 的附加状态及普通命令响应不能触发按键动作。
解析测试覆盖独立字段、正负滚轮、未知子类型和截断状态报文。

## 实机检查

2026-10-20，以下检查在本机固件 `07`、核心 `2` 通过：

1. 读取当前运行配置、通知模式、物理按键和 DPI 档位。
2. 创建多个独立输入句柄，启用通知并请求当前状态。
3. 初始通知的按键、配置和 DPI 档位与 RAM 查询一致。
4. 临时切换运行配置。两个独立读取器都收到新配置通知。
5. 持有特征请求锁时，输入读取和身份查询仍成功。
6. 恢复原配置和通知模式，并读回一致。
7. 再次启用后只释放会话对象，确认析构恢复通知模式。

没有写入闪存。没有生成键盘或鼠标输出。
该检查不验证人工按键、滚轮的完整变化过程。

```sh
env A90_TEST_NATIVE_INPUT=1 cargo test --locked --test vendor_input -- --ignored --nocapture
target/debug/bloody_a90 --watch-native-input 5
```

## 主机动作的剩余实现

EXE `004611a4` 的 `401/402/403/404` 分支执行普通按键和滚轮对应的主机动作。
`406` 使用状态字的低字节作为附加动作索引。
通用解析器从状态报文 `14..15` 读取此字。
本机固件在同一位置写零，因此不能把通用 `406` 路径直接认定为 A90 可用功能。
固件仍保留 162 对附加动作的执行表。其适用触发条件需要继续检查。

普通按键页已接入主机动作执行、保存和配置切换，见 [HOST-BUTTONS.md](HOST-BUTTONS.md)。
诊断会话继续使用整个监听期间的特征请求独占锁。
主机动作服务使用独立通知读取和短期特征请求锁，不在整个运行期间占用配置接口。
现有全局手势继续使用已验证的 evdev 和 uinput 路径。
