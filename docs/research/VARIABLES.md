# 宏变量与条件跳转

分析对象的哈希见 [PROTOCOL.md](PROTOCOL.md)。
本模块只编码、解析和检查内存中的指令，不访问鼠标。
设备执行、状态冲突和中断时序仍未验证。

## 变量编码

EXE 函数 `0060ca14` 将变量名的第四个 UTF-16 字符减去 `a`，生成变量索引。
文本先经 `013c5110` 转换为小写。
该包装函数调用 `0087055c`，后者通过导入表调用 `CharLowerBuffW`。
IAT 地址为 `01644448`，调用跳板为 `013ff762`。

离线接口接受 A 至 Z，对应索引 0 至 25。
固件 `112e` 将指令低字节加 `12`，选择 bank 2 中的目标字节。
`1133` 和 `113a` 分别从后续操作数字的高、低字节读取源索引。
这些是直接内存操作。它们不证明所有变量均与其他宏状态独立。

`bloody-a90-variable.h` 提供以下接口：

- `bloody_a90_macro_variable`：赋值、加、减、AND、OR 和 XOR。
- `bloody_a90_macro_condition`：相等或不等时的相对跳转。
- `bloody_a90_macro_core_variable`：读取内部状态字节。

下表中的 `d`、`l`、`r` 是变量索引，`v` 是 0 至 255 的立即数。
所有字均按小端序保存。

| 操作 | 指令字 | 后续操作数字 |
| --- | --- | --- |
| `d = v` | `8000 OR d` | `v` |
| `d = l` | `8800 OR d` | `l << 8` |
| `d = l + v` | `8100 OR d` | `(l << 8) OR v` |
| `d = l - v` | `8200 OR d` | 同上。 |
| `d = l AND v` | `8300 OR d` | 同上。 |
| `d = l OR v` | `8400 OR d` | 同上。 |
| `d = l XOR v` | `8500 OR d` | 同上。 |
| `d = l + r` | `8900 OR d` | `(l << 8) OR r` |
| `d = l - r` | `8a00 OR d` | 同上。 |
| `d = l AND r` | `8b00 OR d` | 同上。 |
| `d = l OR r` | `8c00 OR d` | 同上。 |
| `d = l XOR r` | `8d00 OR d` | 同上。 |

固件入口 `10ae` 根据指令高字节选择操作。
`10c2` 至 `10de` 处理立即数，`10f0` 至 `1111` 处理变量源。
运算结果写入一个字节，因此加减在 8 位范围内回绕。
编码器只生成这些指令，不计算或执行它们。
SET 忽略接口中的第二源操作数。
其他操作要求第一源为变量，第二源可以是变量或立即数。

## 条件跳转

比较指令总共占三个字。
`delta` 是从比较指令本身开始的 24 位有符号字偏移。

| 条件 | 指令字 |
| --- | --- |
| `l == v` | `8600 OR l` |
| `l != v` | `8700 OR l` |
| `l == r` | `8e00 OR l` |
| `l != r` | `8f00 OR l` |

第二个字为 `(比较值 << 8) OR ((delta >> 16) AND ff)`。
第三个字为 `delta AND ffff`。
变量比较中的比较值是右变量索引。
立即数比较中的比较值是 0 至 255 的字节。

固件 `10e4`、`10ea`、`1118` 和 `111f` 执行比较。
条件成立时，`1141` 把 `03`、`04`、`01` 三字节偏移加到当前指令指针。
条件不成立时，`1148` 跳过三个字。
不能将第三个字独立解析成普通跳转或宏引用。

存储检查器现在同时检查普通跳转和条件跳转。
目标必须位于当前宏内，并且必须是指令边界。
目标可以是 END，也可以构成循环。
检查器不执行条件，不证明宏终止，也不检查变量之间的状态关系。

## 内部状态读取

指令 `9000 OR d` 占两个字，第二个字保存内部源索引。
固件 `1126` 对索引 0、1、2 分别读取当前 bank 的 `5e`、`5f`、`60`。
离线接口只接受这三个索引，不为它们推断产品功能名称。
EXE 文本 `core_var` 固定生成 `9007`，目标为 VarH。
源索引由后续 `dw` 文本提供。

## 射击特殊路径

`00629638` 在每段的左键按下或 NOP 后插入以下文本：

```text
core_var 0
dw 0
var VarH = VarH & 2
dw 1794
if VarH != 0 rgoto -3
dw 255
dw 65531
```

最后一个数值在 B、C、D 路径中为 65532。
其中条件行在 B、C、D 路径中写为 `rgoto -2`。
解析器直接编码条件头，实际偏移由后续原始字确定。

A 路径的七个字为 `9007 0000 8307 0702 8707 00ff fffb`。
B、C、D 路径只把末字改为 `fffc`。
前者的偏移为 -5，后者为 -4，均从条件指令开始。
A 路径因此跳回左键按下指令。
其他路径跳回状态读取指令，跳过此前的左键按下或 NOP。

`special` 字段控制该序列。
每段增加十四字节。
A 路径最多输出 162 字节，B 路径最多输出 276 字节。
循环起点仍按编码后的字偏移计算。
这些结果不证明该条件在本机上何时成立或清除。

## 离线检查

`test-variable.c` 比较全部赋值、算术、位运算和条件指令的原始字。
它检查 24 位偏移边界、错误输出不变，以及跳入操作数字时的拒绝行为。
它还比较 A、B、C、D 特殊程序的完整字序列，并检查最大长度。

`test_variable.py` 通过独立备份解析器检查生成的指令。
检查内容包括源操作数、比较类型、条件目标和特殊序列中的跳转差异。
操作数字中的 END、射击指令值和宏引用值均保留为普通数据。
所有测试均不执行宏或访问鼠标。
