# 应用程序配置关联

本功能读取前台应用，并切换鼠标的运行配置。
规则保存在本机。鼠标不保存程序名称。
关闭工具后，鼠标保持当前配置，自动切换停止。

## 官方程序证据

undelphi 定位了 `TserviceProfileDetector` 的定时器事件 `0069ade8`。
该事件调用 `00492150`，读取前台程序并搜索启用的关联列表。

`00492150` 的调用顺序为：

1. 调用跳板 `013ff948`，IAT `01644584` 指向 `GetForegroundWindow`。
2. 调用跳板 `013ffa5c`，IAT `01644630` 指向 `GetWindowThreadProcessId`。
3. 以访问标志 `0410` 打开该进程，读取程序路径。
4. 提取文件名，并与启用列表中的小写名称比较。
5. 有匹配时返回列表序号，无匹配时返回 -1。

因此应使用前台应用。仅检查进程是否存在不能得到相同结果。

## Linux 实现

`src/foreground.rs` 在 KDE Wayland 上读取
`org_kde_plasma_window_management` 版本 13。
它读取窗口 UUID、应用标识和活动状态，不请求窗口激活或状态修改。
X11 路径读取根窗口的 `_NET_ACTIVE_WINDOW`，然后读取该窗口的 `WM_CLASS`。
Wayland 下不使用 XWayland 的窗口列表，以免漏掉原生 Wayland 窗口。
其他 Wayland 桌面若不提供该接口，界面会报告关联不可用。

Linux 使用窗口应用标识，Windows 使用程序文件名。两者的规则不能直接互换。
界面可以读取当前标识，并用它建立规则。
规则进行完整名称比较。ASCII 大小写不影响匹配。
默认配置用于没有匹配项的应用，也用于桌面没有活动窗口的情况。

工作线程每 750 毫秒检查一次前台应用。全部设备请求在同一线程执行。
应用改变或规则重新应用时，线程选择目标配置。
应用保持不变时，线程不覆盖鼠标按键产生的手动切换。
读取或切换失败时，界面停止自动检查，直到用户重试。

## 鼠标命令

命令 `0c` 的处理程序位于固件 `1322`。
报告第 8 字节写入 RAM `264`，第 9 字节写入 RAM `262`，
第 10 字节写入 RAM `25`。

`Device::select_profile` 保留最大配置序号和按键响应时间。
它向 RAM `262` 写入 `80 OR 目标序号`。
固件 `0694` 等待全部按键释放，然后清除待处理位，把目标序号写入 RAM `263`。
本工具读取待处理位和当前序号，检查切换是否完成。
等待超过一秒时返回错误，并说明鼠标仍可能执行待处理的切换。
该操作不写闪存。

## 实机检查

检查设备为 A90，型号 `04fd`、固件 `07`、核心 `2`。

- KDE 前台读取返回 `brave-browser`。
- 配置 1 切换到配置 2，RAM `262..264` 从 `00 00 06` 变为 `01 01 06`。
- 应用关联规则选择配置 2，保留最大序号和按键响应字节。
- 同一前台应用下，手动切回配置 1 后，下一次关联检查不覆盖该选择。
- 禁用规则后，前台读取不触发配置切换。
- 测试结束后恢复配置 1。
- 手动切换测试后的完整闪存与测试前逐字节相同，共 32768 字节。
  SHA-256 为 `f32caca4fd72a81c8ca3fb823ec1fab26f84f53533659de842abb35945bf2676`。

自动硬件测试默认忽略。它需要稳定的前台窗口，并在结束时恢复原配置：

```sh
env A90_TEST_ASSOCIATIONS=1 cargo test --locked --bin bloody_a90 \
  associations_switch_and_restore -- --ignored
```

X11 测试在独立 Xvfb 服务中检查应用类名、已关闭窗口和空活动窗口：

```sh
xvfb-run -a env A90_TEST_X11=1 cargo test --locked --lib \
  x11_active_window_class -- --ignored
```
