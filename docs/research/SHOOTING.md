# 射击指令与灯效表

分析对象的 EXE 和固件哈希见 [PROTOCOL.md](PROTOCOL.md)。
本轮只读取文件，没有访问鼠标。
以下编码不表示完整射击配置或实机效果通过。

Rust 更新：`src/app/shooting.rs` 连接了七个射击槽位的编辑与保存。
EXE `0061ae3a` 至 `0061afe3` 将七个按下动作放在辅助表索引 1 至 7，
并将七个弹起动作放在索引 9 至 15。索引 0 和 8 为 NOP。
固件 `0762` 与 `0773` 使用射击索引读取这两组动作。
`Configuration::set_shooting` 仅修改指定的一对动作。
保存时仍检查整个主向量的容量。
界面中的位移直接使用设备坐标，Y 向下为正。
本节以下内容保留旧实现的研究过程。

核心差异已经确认：本机核心 2 在 `0708`、`0709`、`072a`、`072b` 使用 NOP，
缺少左键到 `0762`、`0773` 的辅助程序跳转。
官方版本 `0c` 的四份核心固件也有对应差异。
核心 1、2 使用 NOP，核心 3、4 使用左键条件跳转。
完整比较和复现脚本见 [CORES.md](CORES.md)。
因此仅保存辅助表不能让本机核心 2 的左键执行槽位程序。
状态位 `4d.0` 和 `4d.1` 会进入 USB 状态报告。
EXE 的 HID 线程入口为 `0043dc38`。undelphi 的虚方法表将其列为
`TiomHidThreadId7M` 的 slot 2。报告处理函数 `0043e1b4` 把射击状态变化
转为消息 `425`、`426` 和 `427`。`TtheIOM` 的窗口过程 `0044c414`
继续转发为消息 `475`、`476` 和 `477`。主窗体过程 `007ffa5c`
把这些消息转交界面。此路径没有证明主机执行了辅助程序。
接收窗口为 `TformMouseStatusDialog`。构造函数 `004ff3c4` 将窗口过程设为
`00500ddc`。消息 `406` 设置或清除显示标志 `0100`，然后调用 `00502384`
更新浮窗。消息 `403`、`404` 也只更新显示标志和文字颜色。
`00502170` 选择状态图像，`007b0b50` 向调试窗口添加文本。
这条已检查的主机路径负责状态显示，未发现执行辅助程序的操作。
射击页面的验证范围仍是编译和保存。
核心 3、4 的跳转已获得静态证据，但尚未实机验证。
本机尚未用官方软件测试自定义左键程序。
驱动现在从备份中的实际指令识别缺失入口，并在射击页和硬件页显示结果。

## D 类辅助参数

EXE `0061a4ef` 从 D 类槽位读取间隔和 Y 位移。
`0061b000` 至 `0061b05a` 将前 3 个槽位的结果写入辅助表第 17 至 19 字。
其他类型为间隔 100、Y 位移 0。
公式是 `(间隔毫秒 + 设备 Y 位移 × 256) mod 65536`。
间隔超过 255 时，加法会向高字节进位。不能分别截取两个字节后再合并。

`shooting::vertical_parameter` 实现该公式。
`Configuration::set_shooting_parameters` 更新所选槽位对应的一字。
槽位 4 至 7 不修改这三字，其他辅助参数也保持原值。
界面保存 D 类时写入其参数。保存其他类型时把对应字恢复为 100。
测试覆盖正负位移、999 毫秒间隔、无效输入和其他槽位的保留。
这些检查不证明 D 类在本机上的运行效果。

## 射击指令

EXE 函数 `0060ca14` 接受以下内部文本。
每条指令编译成一个 16 位字。
`bloody-a90-macro.h` 保留内部名称，避免推断产品功能名称。

| 内部文本 | 字值 | 编码器输入 |
| --- | --- | --- |
| `shoot index 1` 至 `shoot index 8` | `2610` 至 `2617` | `BLOODY_A90_SHOOT_INDEX`，值 1 至 8。 |
| `shoot exec_delay` | `2608` | `BLOODY_A90_SHOOT_EXEC_DELAY`，值 0。 |
| `shoot enable_mover` | `2609` | `BLOODY_A90_SHOOT_ENABLE_MOVER`，值 0。 |
| `shoot move_recovery` | `260a` | `BLOODY_A90_SHOOT_MOVE_RECOVERY`，值 0。 |
| `shoot paynxlimit` | `260c` | `BLOODY_A90_SHOOT_PAYNXLIMIT`，值 0。 |

`paynxlimit` 是 EXE 中的原始拼写。
这些值可以进入离线直接动作和宏池。
解析器报告原始指令名称和索引。它不执行指令。
索引不是物理按键编号，也不是五组灯效表的偏移。

赋值转换函数 `0062f6c8` 的类型 `1a` 从字段 `+8` 读取索引。
该路径为值 1 至 7 生成 `shoot index` 文本。
底层文本解析器另外接受索引 8。
两处接受范围不同，不能据此声称官方界面提供八种射击模式。

函数 `00619b60` 在特定全局标志下替换触发记录：

| 标志地址 | 触发记录索引，从 0 开始 | 替换后的按下动作 |
| --- | --- | --- |
| `01613a50` | 2 | `shoot index 5` |
| `01613a5c` | 3 | `shoot index 6` |
| `01613a68` | 4 | `shoot index 7` |

触发记录与鼠标外壳按键的对应关系仍需检查。
不能将这些替换规则直接应用到 Linux 按键编号。

## 固件 07 的独立证据

出厂按键表第 12 组按下动作包含 `2613`。
该字与 EXE 的 `shoot index 4` 编码一致。
固件分派表 `0dce` 也包含对应入口。

| 字值 | 固件入口 | 可直接观察的操作 |
| --- | --- | --- |
| `2610` | `0f23` | 将 bank 0 的 `30` 字节设为 0，然后执行共同重置路径。 |
| `2611` 至 `2617` | `0f29` | 将指令低三位写入 bank 0 的 `30` 字节，然后执行共同重置路径。 |
| `2608` | `0ee2` | 读取状态 `30`、`3a` 和 `35 + 索引`，修改指令指针并进入条件路径。 |
| `2609` | `0efc` | 设置当前 bank 的 `00.4` 位。 |
| `260a` | `0efe` | 检查并处理累计位移，清除 `1a` 至 `1d`。 |
| `260c` | `0ec3` | 设置状态位，并根据其他状态选择后续路径。 |

共同重置路径位于 `0f39`，并调用 `1078`。
这说明索引影响运行状态。它不是宏存储指针。
这些处理函数没有将随后的字作为额外操作数读取。
`2608` 包含条件控制，不能将它等同于普通毫秒延迟。

宏检查器检查存储宽度、END 位置，以及普通和条件跳转的目标。
它不执行条件，也不检查射击状态、位移恢复效果或中断时序。
完整配置仍需还原其余 M 类语法和触发槽位，并验证设备行为。

## A 类连击程序

真正的射击程序编译入口是 `00628c8c` 和 `00629638`。
它们生成辅助动作中的程序，与灯效向量不同。
`00628c8c` 生成固定双击、三击和四击。
其按下间隔为 25 毫秒，中间释放间隔为 85 毫秒。
这些字值与已经解析的出厂点击宏一致。

`00629638` 根据 `状态对象 + 38 + 槽位` 的类型字节选择路径。
已定位类型 `A`、`B`、`C`、`D` 和 `M`。
新模块 `bloody-a90-shooting.h` 实现 A 类的普通路径和特殊路径。
B、C、D 类的两种路径也已实现，见下一节。
M 类目前支持部分普通文本的离线编译，见 [TEXT.md](TEXT.md)。

A 类记录位于 `状态对象 + 40 + 槽位 * 60`。
这里的偏移均为十六进制字节。

| 记录偏移 | 源码中的用途 |
| --- | --- |
| `1c` | 连击次数。 |
| `20` 起的五个整数 | 各次点击的间隔参数。 |
| `34` 起的五个整数 | 第一组位移参数。 |
| `48` 起的五个整数 | 第二组位移参数。 |
| `5c` | 末尾是否追加 `shoot move_recovery`。 |
| `5d` | 是否插入额外的特殊指令序列。对应输入字段 `special`。 |

字符串拼接函数的参数表明，EXE 生成 `mover <第一组值> <-第二组值>`。
这确认了两组参数在指令中的轴顺序和第二轴的符号转换。
参数与界面单位的关系仍需检查。

`A90Decompile.java` 修正了整数转字符串函数 `0040f140` 的调用约定。
该函数从栈中读取目标和整数，调用者移除八字节参数。
这个修正使射击编译函数中的动态间隔和位移值可以直接读取。
之前的无参数反编译结果省略了这些实参。
脚本还修正了三个字符串拼接函数 `013c4e68`、`013c5500` 和 `013c55a4`。
它们从栈中读取目标、左字符串和右字符串，调用者清理参数。
后两者分别将 ASCII 和 UTF-16 左字符串转换后拼接。

离线编译器接受以下输入：

- 1 至 5 次点击。
- 每次点击的间隔参数，范围 1 至 999 毫秒。
- 点击之间的设备 X/Y 位移，范围 -126 至 126。
- 是否在末尾恢复位移。
- 是否在左键按下之后插入特殊条件序列。

X/Y 输入已经是设备坐标。调用者仍需完成界面坐标转换。
编译器不会读取官方配置文件或推断其坐标方向。
最后一次点击不产生补偿位移，其 X/Y 值不参与编译。

每次点击先生成左键按下、`shoot exec_delay`、按下延迟和左键释放。
当间隔小于 40 时，按下和释放延迟均为 `max(1, 间隔 / 2)`。
除法丢弃小数。因此参数 39 生成两个 19 毫秒延迟。
当间隔至少为 40 时，按下延迟为 20，释放延迟为 `间隔 - 20`。
最后一次点击省略释放后的延迟和位移。
这些是生成的延迟参数。设备状态仍可改变执行路径。

每次补偿位移前追加 `shoot enable_mover`。
当任一轴的绝对值超过 63 时，编译器将两轴分成两次移动。
第一部分按向零方向除以二，第二部分保留余数。
每次移动分别具有自己的 `enable_mover` 前缀。
即使位移为零，EXE 的该路径仍生成一次移动。
输入范围保证拆分后的每个轴都能无损编码为 7 位有符号值。
超出范围时返回错误，不采用 EXE 可能产生的截断。

恢复选项在末尾追加 `shoot move_recovery`。
编译器最后追加 END。普通路径最多输出 92 字节，特殊路径最多输出 162 字节。
它生成一段完整宏，不生成射击索引、释放动作或设备写入。
该宏可以进入现有配置构建器的辅助动作，但槽位对应关系仍需核对。

## B、C、D 类循环程序

`bloody_a90_compile_shooting_cycle` 实现 `00629638` 的 B、C、D 普通路径和特殊路径。
它同时生成按下程序和释放程序。
所有程序均包含 END。输出不包含设备地址或传输报告。
发生错误时，整个输出对象保持原值。

| 类型 | 记录基址 | 次数 | 间隔数组 | 第一轴数组 | 第二轴数组 | 循环起点 | 恢复标志 | 特殊序列标志 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| B | `状态 + 2e0 + 槽位 * 88` | `1c` | `20` | `40` | `60` | `80` | `84` | `85` |
| C | `状态 + 698 + 槽位 * 8c` | `20` | `24` | `44` | `64` | `84` | `88` | `1c` |
| D | `状态 + a6c + 槽位 * 28` | 固定为 1 | `1c`，单值 | 不生成 | `20`，单值 | 固定为首条 | `24` | `25` |

表内偏移均为十六进制字节。
B、C 的数组各有八个整数。
EXE 中的 B、C 循环起点从 1 开始，编码器输入 `loop_start` 从 0 开始。
循环分支指向所选段的第一条指令。
前面的段只在首次进入程序时执行。

B 类的每一段生成左键按下、两段延迟和左键释放。
延迟分配规则与 A 类一致。
每一段都生成尾部延迟和补偿位移，包括最后一段。

C 类只在第一段生成左键按下。
后续段在相同位置生成 NOP。
该路径不生成左键释放指令。
两段延迟和补偿位移仍在每段生成。
这些结论描述指令序列。实际按住、停止和恢复效果仍需实机验证。

D 类只有一段，只使用第二轴位移。
它总是将间隔参数向零除以二，再将每段延迟的最小值限制为 1。
它不采用 A、B、C 类在参数达到 40 时使用的 `20 + 剩余值` 规则。
例如 D 类参数 999 生成两个 499 毫秒延迟参数。

B、C、D 的位移拆分规则与 A 类相同。
输入均采用转换后的设备坐标，位移范围为 -126 至 126。
D 类忽略 X 输入。B、C 允许 1 至 8 段，D 只允许一段。
普通按下程序最多为 164 字节，特殊按下程序最多为 276 字节。

未选恢复时，释放程序为 `delay 16`、`stop`、END，共六字节。
选中恢复时，在它前面追加 `delay 16`、`shoot move_recovery`，共十字节。
释放程序中的延迟是普通延迟，没有 `shoot exec_delay` 前缀。
当前实现不生成额外的左键释放指令，保持该 EXE 路径的原始序列。
辅助动作中的按下、释放槽位对应关系仍需核对。

`special` 非零时，每段在左键按下或 NOP 后插入七个字。
该序列读取内部状态，将 VarH 与 2 执行 AND，然后根据结果跳回。
A 类跳回左键按下，B、C、D 类跳回内部状态读取。
条件指令占三个字，存储检查器检查其跳转目标。
编码和固件入口见 [VARIABLES.md](VARIABLES.md)。
设备何时清除该状态，以及特殊路径的实际效果，仍未验证。

## M 类宏来源

`00629638` 的 M 分支使用 `状态对象 + b84 + 槽位 * 3c` 作为记录基址。
以下偏移均相对此记录，单位为十六进制字节。

| 记录偏移 | 编译时的用途 |
| --- | --- |
| `14` | 文本格式标记。转换为小写后与 `highlanguage` 比较。 |
| `30` | 复制到动作对象 `+8` 的重复模式。普通宏编译器处理该字段。 |
| `34` | 宏文本。先去除首尾空白，再转换为小写。 |

标记为 `highlanguage` 时，EXE 将文本传给 `006134b4`。
其他格式直接使用处理后的文本。
该分支随后调用 `0062714c`、`0062200c` 和 `0060c510`。
这是文本编译路径，没有在该分支中按文件路径读取宏。

`006134b4` 先调用 `006144a8` 处理输入，再按首个词分派：

| 首个词 | 处理函数 |
| --- | --- |
| `if` | `00615f18` |
| `ifkey` | `00616474` |
| `repeat` | `006168f0` |
| `keyboard` | `00614ea0` |
| `mousebutton` | `00615144` |
| `mousewheel` | `006157f4` |
| `mousemove` | `00615aac` |
| `delay` | `00614ad8` |
| `math` | `00616f4c` |
| `gotoflag` | `00617438` |

首个词为 `flag` 的行在此阶段保留。
后续阶段通过 `006177e4` 查找标记，将相关行转换为相对跳转。
可以观察到 `rgoto`、`rgoto_24bit` 和 `rgoto_24bit_highlanguage` 三种输出文本。
最后，标记行替换为 `null`。
这些入口已经定位，但各词的完整语法、展开规则及行号换算仍需还原。
`macro_text.py` 现支持部分普通 M 类文本，并修正展开后的跳转偏移。
HighLanguage、文件导入和其余语法仍需实现，不能据此宣称支持完整官方 M 类配置。

## 五组灯效数据

此前将编译器末尾的五组向量称为射击表。这一判断不正确。
它们由函数 `0062c498` 生成。
该函数引用以下 UTF-16 文本：

| 字符串地址 | 内容 |
| --- | --- |
| `014e0fde` | 模式编号、指令、画格。 |
| `014e101a` | 模式编号、来源档案格式、全彩。 |
| `014e103c` | 模式编号、呼吸灯周期。 |
| `014e10d2` | 模式编号、来源档案格式、动漫。 |
| `014e110a` | 模式编号、指令、静态图，重播时跳过。 |
| `014e1134` | 模式编号、播放长度，分钟。 |
| `014e11b6` | 模式编号、来源档案格式、演算特效。 |

函数还区分未设定、全彩、动漫和演算特效。
RGB 打包函数 `0062f640` 对每个颜色保留低三个字节。
它将连续颜色字节写入灯效记录。
这与普通鼠标宏的指令格式不同。

`00619b60` 的内部存储路径执行以下操作：

1. 依次保存五组灯效向量的起始字偏移。
2. 追加各向量，然后追加标记 `a4a4`。
3. 将头部第 13 字设为随后列表的起始偏移。
4. 为每组追加两个字：向量偏移和零。

因此列表包含十个字，不能将其当作五个单字宏引用。
另一条路径使用外部存储和不同引用，仍需独立分析。
固件 `14c0` 和 `14d5` 也以两字步长访问第 13 字指向的列表。
这些格式证据不能证明本机 A90 支持 RGB 或动画灯效。
当前 A90 驱动仍只提供已经验证的单色亮度。

## 离线检查

`test-macro.c` 比较全部十二个指令字及错误参数。
`test-storage.c` 检查这些指令的存储宽度。
`test_flash.py` 检查索引、控制指令及操作数字中的同值数据。
`test-configuration.c` 和独立 Python 预期向量检查两个直接射击索引。
所有检查均使用内存缓冲区。

`test-shooting.c` 比较 A 类三次点击的完整字节序列。
它检查间隔 1、39、40、41 和 999 的边界行为。
它遍历 64009 组 X/Y 输入，独立解码后检查位移总量。
其他检查覆盖最大长度、错误输出不变，以及输入与输出重叠。
`test_shooting.py` 通过备份解析器独立检查生成的延迟、补偿和恢复指令。
