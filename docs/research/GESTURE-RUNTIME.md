# Linux 全局手势

实现位于 `src/gesture_runtime.rs`、`src/linux_input.rs`、`src/host_program.rs`、`src/host_open.rs` 和 `src/gesture_tip/`。
方向和文件格式证据见 [GESTURES.md](GESTURES.md)。

## 输入路径

程序从 sysfs 查找物理 A90 的鼠标事件接口。
候选必须具有 USB ID `09da:fafd`，并支持相对 X/Y 位移。
查找会排除 `/sys/devices/virtual`，避免虚拟输出被再次读入。
本机接口检查结果为 `/dev/input/event5`，名称 `COMPANY  USB Device`。
它提供按键 272 至 279，以及相对轴 0、1、8、11。
这些分别包含五个普通鼠标按键、X/Y、滚轮和高分辨率滚轮。

启用时，程序先创建虚拟鼠标和虚拟键盘，再接管物理鼠标接口。
虚拟鼠标复制物理鼠标的名称、身份和按键、相对轴能力。
普通移动和按键经过虚拟鼠标转发。
程序按 `SYN_REPORT` 合并 X/Y 位移，保留输入帧的方向。
触发键按下后，位移进入识别器，并停止向桌面移动指针。
普通触发键未移动时，在释放时生成原点击。
移动后没有匹配方向时不生成点击。
按下其他鼠标按键会取消当前笔画。
同时按下右键和中键会停止全局手势。

两套手势可以选择不同的普通鼠标按键。
“按键”页需要先把实际触发键设为对应的鼠标按键输出。
配置不会自动覆盖鼠标中的已有按键表。
这使全局手势也能使用映射成普通鼠标按键的顶部按键。
按键页也可直接指定“主机动作 → 16 合一手势 / 鼠标手势”。
这条路径使用物理状态位，支持顶端“1 / C / 3”键和按配置分配。
它与上述普通触发键共用识别器和输入接管，不要求输出一个普通鼠标按键。
保存、停止和原生通知的顺序限制见 [HOST-BUTTONS.md](HOST-BUTTONS.md)。
距离使用原始相对位移，不是经过桌面加速度计算的屏幕像素。
16 合一支持释放识别和按距离即时响应。
普通鼠标手势在释放时选择方向。

## 浮动提示板

普通鼠标手势的 `EnabledTipBoard` 现在控制浮动提示板。
触发键按下后显示笔画、当前匹配方向和动作文字。
松开触发键、取消笔画或停止运行后隐藏。
关闭选项后不创建提示窗口。
提示板使用独立显示线程，输入线程只提交有上限的状态快照。
状态更新最多约每秒 30 次，旧快照会被新快照替换，不积累绘图请求。
笔画最多保留 2048 个显示点。达到上限后会降低显示采样密度，识别器仍接收原输入。

Wayland 使用 `zwlr_layer_shell_v1` 的 Overlay 层。
它设置空的鼠标输入区域，并禁止键盘交互，不保留桌面工作区域。
合成器选择输出，提示板位于该输出右上角。
当前 KWin 提供协议版本 5。实现使用至多版本 4 的请求。
不提供该协议的 Wayland 桌面需要关闭提示板选项，仍可使用手势本身。
X11 使用不受窗口管理器管理的浮动窗口，输入区域为空，且不请求键盘焦点。
X11 提示板位于触发时的指针附近。
两种后端都把相对笔画缩放到提示板内，窗口不作为鼠标输入源。

官方窗口为 `TTipBoardForm`，VMT `0160bb0c`。
资源包含轨迹绘图区、方向图像和动作文字，使用透明、无边框窗口。
创建、显示和输入入口分别为 `013ecbc4`、`013ecc0c` 和 `013ecb38`。
Linux 提示板自行绘制，不包含官方图像。

## 动作执行

启用前会检查全部已启用方向的动作，并预读、编译 AMC 文件。
16 合一即时模式只检查前八个方向。停用的折线动作和另一套停用的手势继续保留，但不初始化它们的桌面接口。
目前支持以下 Simulator：

| 类型 | 动作 |
| --- | --- |
| 0 | 空动作 |
| 1 | AMC 宏，含 HighLanguage |
| 6 | 键盘及左右修饰键组合 |
| 7 | 常用媒体、浏览器和编辑 Consumer 键 |
| 8 | 电源、睡眠、唤醒 System 键 |
| 9 | 五个鼠标按键和上下、左右滚轮 |
| 20 | 打开程序、文件、目录或 URL |
| 21 | KWin EIS 或 Wayland 虚拟键盘 Unicode 文字输入 |
| 22 | 应用缩放，使用 Ctrl 配合一格滚轮 |
| 24 | 指针下窗口的最小化、最大化，以及当前 KDE 桌面的全部最小化 |

普通按键动作支持 `Action=0..3`。
两套官方结果处理器分别在 `00464e61` 和 `004651b7` 压入阶段值 2。
因此结果按释放阶段处理：`Action=0/2` 只发送释放，`Action=1` 不产生事件，`Action=3` 发送完整点击。
滚轮使用 `Action=3..6`。
无法执行的动作会在启用前显示方向和错误原因。
它们仍可在文件编辑器中保留和导出。

Simulator 20 从 `MacroName` 读取目标，不使用 `MacroPath`。
`0045db32` 读取记录偏移 `18`，`00546eb0` 的比较诊断将此字段命名为 `.sMacroName`。
调用点 `0045db4a` 经 IAT `0164402c` 进入 `ShellExecuteW`，目标不带独立参数。
Linux 使用完整目标字符串。普通可执行文件直接启动，其他文件、目录和 URL 交给 `xdg-open`。
桌面入口文件也交给桌面处理，不作为二进制直接执行。
本地相对路径会转换为绝对路径，命令行参数不会从目标字符串中拆出。
启动和进程回收均在独立线程中进行，输入线程不会等待程序启动或退出。
请求队列有上限。“中断宏”会取消未开始的请求，已启动的应用可以继续运行。
启动或打开失败会显示状态消息，普通输入继续转发。
此类型在释放结果中只有 `Action=3` 会打开目标，与官方分支条件一致。

Linux 扩展字段 `LinuxArguments` 提供独立参数，每行一个。
非空时，目标必须是可执行的普通文件，不能是 URL、目录或桌面入口文件。
空格、引号、`$()` 和其他字符按原文传给程序，不经过命令解释器。
空行生成空参数，末尾换行不增加参数。支持 LF 和 CRLF。
参数上限为 128 个，总文本上限为 64 KiB。
参数为空时使用原来的打开路径，既有手势无需修改。
此字段随手势 XML 和关闭时的草稿一起保存。
截图、桌面画笔和语音工具使用此调用方式，见 [HOST-SPECIAL-ACTIONS.md](HOST-SPECIAL-ACTIONS.md)。

还确认 Simulator 21 从记录偏移 `10`，即 `.sHintText` 读取待输入文字。
其入口 `00460054` 逐个 UTF-16 单元发送 Unicode 按下和释放事件。
它跳过 CR，并把 LF 转为 Enter。结果阶段只有 `Action=3` 执行输入。
Linux 使用 Unicode 标量值。KWin 路径通过 libei 1.6 的文字键符接口发送按下、释放和各自的帧。
中文和补充平面字符不依赖当前键盘布局。换行发送 Return，制表符发送 Tab。
文件保存时把 CR 写为 XML 字符引用，避免解析器将其改为 LF。

文字后端优先通过 D-Bus `org.kde.KWin.EIS.RemoteDesktop.connectToEIS(1)` 取得连接。
它只绑定 EIS 文字能力，并在设备恢复后发送事件。
启用全局手势前会等待接口检查。检查失败时不接管鼠标。
libei 按需动态加载。未配置文字动作时不需要此库。
此路径适用于支持 EIS 文字设备的 KWin Wayland，本机 KWin 6.8.0 的连接检查通过。
如果此接口不可用，后端会检查 `zwp_virtual_keyboard_manager_v1`。
第二条路径使用虚拟键盘专用的 XKB 映射，不依赖物理键盘布局，也不使用剪贴板。
独立 Sway 1.12 / wlroots 0.20.2 与原生 Qt 编辑器检查通过。
初始化只创建键盘并检查映射，不发送按键。检查超时或失败时不接管鼠标。
当前虚拟键盘后端要求一个 Wayland 座席。
映射格式、检查方法和其他桌面的限制见 [WAYLAND-TEXT.md](WAYLAND-TEXT.md)。
X11 和未提供这些接口的 Wayland 桌面仍不支持文字动作。

文字长度上限为 64 KiB。文字在独立线程执行，两个请求队列各最多保存八项。
中断操作取消未开始的请求，并在当前字符释放后停止剩余文字。
停止全局手势会关闭文字设备和 D-Bus 连接。
设备暂停或移除时，文字请求显示错误，普通鼠标输入继续转发。
实现依据来自本机 `/usr/include/libei-1.0/libei.h` 和
[KWin EIS 连接实现](https://github.com/KDE/kwin/blob/master/src/plugins/eis/eisbackend.cpp)。

Simulator 24 的 `Object=1` 最小化指针下窗口，其他非零值最大化该窗口。
`Object=0` 在 Linux 中执行当前 KDE 桌面和活动的全部最小化。
Windows 对该值生成 Win+M 硬件宏，而原主机分派器不执行动作。转换证据见 [KEY-MENU.md](KEY-MENU.md)。
结果阶段只有 `Action=3` 执行。最大化不会切换为还原。
`00460288` 检查 `WS_MINIMIZEBOX`，并在 `004602df` 压入 `SC_MINIMIZE=0xf020`。
`0046021c` 检查 `WS_MAXIMIZEBOX`，并在 `00460273` 压入 `SC_MAXIMIZE=0xf030`。
两条路径都使用 `GetCursorPos`、`WindowFromPoint` 和顶层窗口选择函数 `004601ac`。
`013ffb70` 经 IAT `016446e0` 调用 `PostMessageW`，消息为 `WM_SYSCOMMAND=0x112`。

KWin 后端使用 `workspace.windowAt(workspace.cursorPos, 1)` 选取窗口。
它检查窗口能力后设置 `minimized=true` 或调用 `setMaximize(true, true)`。
脚本通过独立 D-Bus 回调返回结果。回调只接受当前 KWin 总线所有者的消息。
X11 后端沿指针下的窗口层级查找 `WM_STATE`，也检查窗口边框中的客户窗口。
它根据 `_NET_WM_ALLOWED_ACTIONS` 决定是否发送 `WM_CHANGE_STATE` 或添加两个最大化状态。
窗口不支持动作时保持原状。两种后端都使用指针下的窗口，不主动改变键盘焦点。

窗口服务在接管鼠标前检查接口，在独立线程执行，待执行队列最多十六项。
中断取消尚未开始的动作。错误显示到状态栏，普通输入继续转发。
KWin 的临时脚本使用独立目录，目录权限为 `0700`，文件权限为 `0600`。
每次请求结束后卸载脚本并删除文件，服务退出后删除目录。
接口依据见 [KWin 脚本 API](https://develop.kde.org/docs/plasma/kwin/api/)
和 [EWMH 窗口属性](https://specifications.freedesktop.org/wm-spec/latest/ar01s05.html)。

Simulator 22 的 `00465770` 通过 `GetProcAddress` 调用 `GoZoomEvent`。
构造函数 `00465628` 加载 `DLL_ZoomControl.dll`。
DLL 按 Windows 窗口类别分发缩放动作，其中 `100017a0` 使用 Ctrl、1 ms 等待和一格滚轮。
Linux 使用此组合。`Object=0` 放大，其他非零值缩小，结果阶段只有 `Action=3` 执行。
应用需支持 Ctrl+滚轮。使用其他绑定的应用可以指定键盘动作或 AMC 宏。
隔离 uinput 检查确认按键、滚轮的时间顺序。独立 Qt 窗口检查确认字体放大、缩小和 Ctrl 释放。
DLL 证据和验证范围见 [ZOOM.md](ZOOM.md)。

主机宏执行器复用 M 型宏编译器。
它支持键盘、修饰键、Consumer/System 键、鼠标按键、位移、滚轮和延迟。
它还支持变量、条件、相对跳转、`gowhile`、`ifkey` 和三种重复设置。
变量按 8 位运算并回绕。
`core_var` 和 `ifkey` 使用已验证的物理按键状态读取，不从输出按键猜测物理记录。
启用前检查已启用宏的按下和弹起程序。需要物理状态时，先检查 HID 访问，再接管鼠标。
状态读取在独立线程中执行。输入线程只使用十毫秒内的样本。
没有新样本时，本次 VM 执行等待，普通鼠标事件继续转发。
厂商 HID 接口由整个操作持有独占锁，配置保存和状态读取不会交错请求。
读取线程遇到占用时会重试，三秒后仍无法访问则报告错误并停止当前宏。
停止运行时，先释放物理输入接管，再等待读取线程退出。
读取暂时失败时只停止当前主机宏，普通输入继续转发。
需要固件内部状态的 DPI、灯光、射击等宏指令暂不在主机执行。
这类宏仍可通过现有按键页保存到鼠标执行。

一次宏执行按下程序，然后执行释放程序。
即时手势中的按住重复宏在松开触发键时转入释放程序。
释放识别中的按住重复宏执行一次。
开关重复宏在下一次匹配同一手势时转入释放程序。
新的不同手势会先停止当前循环宏，再执行新动作。
“中断宏”同时中断设备宏和主机宏。
宏执行按时间分段，等待延迟时仍处理物理输入。
一次运行步数和待执行动作队列均有上限。

物理按住和宏生成的鼠标按住分别记录。
宏释放按键不会释放仍在物理按住的同名按键。
生成滚轮动作时，会同时发送设备支持的高分辨率伴随事件。
停止、断开、输入队列丢失和线程退出都会销毁虚拟设备并释放接管。
虚拟设备销毁前会释放生成的按键。
