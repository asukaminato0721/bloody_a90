# 普通手势方向边界

## 原程序的角度换算

EXE SHA-256：`4a76f6ef4b6e7da699afbd8d3d780ae9747b599af795531a39e3eb5d93c93162`。

`013ef8a4` 用两点之差计算方向角。
平方根结果先保存为 binary64，再计算 `acos(-dy / distance)`。
随后乘以地址 `013ef94c` 处的 binary64 常数。
该常数的位模式为 `404ca99461d59ae7`，数值为 `57.324840764331206`。
它等于 `180 / 3.14`，与标准的 `180 / π` 不同。
负 X 方向再对角度取负。

调用点 `013ef291` 将角度保存为 binary64。
`013ef309` 把它传给方向分类函数 `013ef954`。
分类函数使用 `-135`、`-45`、`45`、`135` 这些边界。
因此误差来自换算常数，不能只按理想几何斜线处理。

| 位移 | 旧的理想角度分类 | 原程序分类 |
| --- | --- | --- |
| `(100, -100)` | 上 | 右 |
| `(100, 100)` | 右 | 下 |
| `(9993, -10000)` | 上 | 右 |

Linux 现使用原常数和 acos 路径。
正常位移范围中的方向结果与原函数匹配。
零位移仍返回空方向，由采样距离规则排除。
Linux 使用宽浮点计算平方，避免原程序在大整数平方时的溢出。

## 原函数对照

`a90-direction-probe.c` 是独立的 32 位 Windows 数学探针。
它通过 `LoadLibraryExW` 映射已验证的 EXE，不调用 EXE 入口，也不解析其导入。
Wine 在此模式下未应用 EXE 重定位，因此探针对私有内存映像应用标准 HIGHLOW 重定位。
它处理跨页地址，并在调用数学函数前恢复页面权限。
原文件不改变。脚本会在运行前后检查文件哈希。

探针只调用 `013ef8a4` 和 `013ef954`。
其导入表只有 KERNEL32 中的命令行、映像加载、页面权限、标准输出、错误查询和退出函数。
不启动官方界面，不调用硬件命令。
EXE 映射行为见 [LoadLibraryExW 文档](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw)。

对照共生成 `2,362,368` 行参考结果。
x87 控制字 `037f` 和 `027f` 各生成 `1,181,184` 行，分别检查扩展精度和双精度运算。
样本包含小位移网格，以及 16 位位移范围内选定的斜线和附近向量。
最大绝对 X 分量为 `32796`，最大绝对 Y 分量为 `32768`。
这不是对整个整数平面的穷举。
Rust 对全部参考行的方向分类均一致。

仓库保留 284 行原始结果作为常规回归数据。
它们包含原函数的方向值和角度位模式，不由 Rust 分类器生成。
