# 固件 0C 与 07 的差异

2026-10-21，用户用官方 Bloody 8（Windows 虚拟机）把 A90 从固件 `07` 更新到 `0C`。
更新后鼠标枚举为 USB `09da:5450`，bcdDevice `0.0c`（此前为 `09da:fafd`、`07`）。
本文离线比较官方四份 `0C` 图像与本机 `07` 闪存备份，没有访问 USB。
固件文件的解码方法和哈希见 [CORES.md](CORES.md)。地址均为字地址。
实机读回为核心 1。静态比较以核心 2（更新前的核心）为准；
四个核心之间的 18 个差异字见 [CORES.md](CORES.md)。

## 结论

`0C` 是 `07` 的小幅修订，命令集、写入路径和闪存分区不变。
驱动依赖的大部分事实仍然成立，但有几处固定地址需要按固件区分。
驱动现已接受 `0c` 的识别和读取，见文末的实机核对。

| 项目 | `07` | `0C` | 对驱动的影响 |
| --- | --- | --- | --- |
| USB ID | `09da:fafd` | `09da:5450` | 设备查找和 udev 规则需加入 `5450`。 |
| 厂商接口 | 用途页 `ff32`，用途 `04fd`，报告 7 | 用途等于型号字 `04fc` 至 `04ff`，其余相同 | 查找接口时接受四个用途。 |
| 命令表 | `1193` | `11d1` | 同一组 48 个命令都存在，处理程序整体后移。 |
| 写入命令 `2f` | `137a`，范围 `2400` 至 `3e00` | `13b8`，指令逐条相同 | 写入范围和页擦除规则不变。 |
| 灵敏度保存表 | `2400` | `2400` | 无。 |
| 按键保存区 | `2600` 至 `3cff` | 相同 | 无。 |
| 处理程序页 | `3d00` | `3d00`，仅 `3d08` 的跳转目标随代码后移 | 仍不得写入。 |
| 出厂数据头 | `17fa` | `1838` | 备份解析需按 `RIDATA` 头定位。 |
| 出厂灵敏度表 | `1806` | `1844` | `backup.rs` 中的固定地址需按固件选择。 |
| 出厂按键表 | `183c` | `187a`，内容相同 | 同上。命令 `05` 本身报告这些地址。 |
| 左键射击入口 | `0708`、`072a` | `0717`、`0739` | `shooting_route` 的代码窗口需按固件区分。 |
| 识别命令 `1f` | 型号 `04fd`，固件 `07` | 型号 `04fc` 至 `04ff`（核心 1 至 4），固件 `0c` | 型号字可直接读出核心。 |

## 方法

`contrib/research/compare-firmware.py` 解码指定核心的 `0C` 图像，
按 SN8F2288 操作码对齐 `0100` 至 `1bff` 的代码，
再列出插入的代码段和操作数不同的对齐指令。
跳转目标若指向对应的对齐位置，不计为差异。
输出只含地址、字值和描述符片段，不输出固件。

```sh
python3 contrib/research/compare-firmware.py \
  /home/w/gitproject/BloodyWorkShop8/BloodyWorkShop8.exe \
  /home/w/gitproject/BloodyWorkShop8/FW/USB \
  /home/w/.cache/a90-unlocked-flash-backup.bin 2
```

## 闪存分区

图像的 `0000` 页为零，`3f00` 页不在图像中。
图像的 `2400`、`2500` 页分别是新的引导页和设备数据页，
与 [WRITES.md](WRITES.md) 中命令 `1e` 的复制方向一致：
`2400` 复制到 `0000`，`2500` 复制到 `3f00`。
`1c00` 至 `23ff`、`2600` 至 `3cff` 两图都为零，`3e00` 页相同。

## 代码差异

除去地址整体后移，只有以下变化。

| `0C` 地址 | 长度 | 内容 |
| --- | --- | --- |
| `05ef` | 16 | 接口 2 的报告描述符新增一个鼠标集合：报告 ID 4，X/Y 各 16 位相对值，范围 ±32767。描述符长度 `85` 改为 `a5`。 |
| `0a80` | 42 | 两个对称函数，把 X、Y 位移累计值（bank 2 的 `58/59`、`5a/5b`）右移一位并四舍五入，结果非零时置位 `4a.2`。`08ca` 只在回报率编码 RAM `23` 的位 4 置位时调用，即位移减半。尚未发现写入该位的官方路径。 |
| `0f01`、`1443` | 各 1 | `RET` 填充或分支调整。 |
| `1903`、`191a` | 各 2 | 写 RAM `4b` / `4d` 的常数由固定 `10` 改为 `01`、`03` 或 `10`，取决于 `66.5` 和 `4a.5`。 |
| `1a17`、`1a5d` | 3、12 | 传感器初始化状态机（`5e` 为状态号）新增步骤：读寄存器 `1a`，经右移、加 `23`、异或 `5a` 后写入寄存器 `1b`；另写 `1a=11`、`5d=81`、`7f=00`。`1a8f` 经 `UDR0_W` 位 4 至 6 串行写寄存器（地址或 `80`）。这不是指示灯程序。 |
| `1acb` | 1 | 计数比较常数 `0f` 改为 `0a`，用途未确认。 |
| `1b5f` | 1 | 新增空返回，命令 `03` 的路径改为调用它。 |

灯效列表读取函数（`07` 的 `14c0`、`14d5`，`0C` 的 `14ff`、`1514`）在 `0C` 中仍没有调用者。

RAM 只有 bank 0 的 `65` 改为 `66`（识别命令和状态位使用）。
驱动读取的 RAM 地址 `23`、`25`、`4b`、`111`、`112`、`157`、`162`、
`25e` 至 `264` 在对齐代码中的引用都没有变化。
新代码写入 `4b` 的位 0 时也保留通知开关的语义，但仍需实机读回确认。

## 出厂数据

出厂按键表 127 个字完全相同。出厂灵敏度表有 6 个字不同：

| 偏移 | `07` | `0C` | 含义 |
| --- | --- | --- | --- |
| `14` | `0091` | `004a` | 第 5 档传感器编码：6200 改为 3200 DPI。 |
| `18`、`19` | `0067` | `007b` | 未启用的第 7 档 X/Y 比例。 |
| `1b`、`1c` | `0067` | `0040` | 未启用的第 8 档 X/Y 比例。 |
| `1e` | `0002` | `0001` | 默认回报率编码：500 Hz 改为 1000 Hz。 |

这些字由 `template_from_factory` 原样带入新模板，不需要特殊处理。

## 设备数据和授权字

| 字 | `07` 闪存 | `0C` 图像 |
| --- | --- | --- |
| `3ff0` | `fffe` | `ffff` |
| `3ff3` | `ffff` | `ff66` |
| `3ff9` | `ffff` | `0000` |
| `3ffc`、`3ffd` | `2543 8614` | `257f 87ff` |

[WRITES.md](WRITES.md) 记录 `07` 在 `3ff3` 低字节位 0 为 1 时跳过宏中的位移。
`0C` 图像的低字节为 `66`，但更新程序没有写入 `3f00` 页的这个字，实机仍为 `ffff`。
命令 `2a` 的授权密钥字节由 `17 67 40 91` 变为 `17 62 49 9a`。本工具仍不发送 `2a`。

USB 设备描述符从 `0520` 起。`0C` 图像中的 VID/PID 是占位值（核心 2 为 `1956:fefd`），
更新程序写入时把 `0526` 至 `0529` 改成 `09da:5450`，见下节的实机读回。

## 驱动支持

- 设备查找、手势指针、KWin 设置和 udev 规则同时接受 `fafd` 和 `5450`。
  `0C` 在接口 2 新增的相对指针不作为手势输入，手势只读取接口 1。
- `Device::open` 接受 `Layout::ALL` 中的固件（`07`、`0c`），型号掩码仍为 `04fc`。
- `backup::Layout` 记录两版的出厂表地址和左键射击入口；备份解析按出厂数据头的
  型号字和固件字选择布局。
- 核心号改由型号字计算。识别响应字节 9 在四个核心图像中都是 `22`，不是核心号。

## 实机只读核对

2026-10-21，更新后的鼠标只发送识别、命令 `05`、亮度读取和整片闪存读取，没有写入。

- 识别：型号 `04fc`、固件 `0c`，即核心 1。厂商接口的用途也是 `04fc`；
  四个核心图像的用途分别等于各自的型号字，查找接口时已接受 `04fc` 至 `04ff`。
- 命令 `05`：灵敏度 `2400`、按键 `2600`、设置 `3e00`、出厂灵敏度 `1844`、
  出厂按键 `187a`、设备数据 `3ff0`，与静态分析一致。
- 代码区 `0100` 至 `1bff` 与核心 1 图像只差 `0526` 至 `0529` 四个字，即上述 VID/PID。
  `3d00` 页与图像相同，`1c00` 至 `23ff` 仍为零。
- `0000` 页与更新前的 `07` 闪存完全相同：更新没有改写引导程序，
  图像暂存页 `2400` 的内容没有被复制过去。
- `3f00` 页与更新前只差 `3ff4` 至 `3ff7`（`9bce 8fa0 0200 2019`），
  前两个字即官方程序显示的机身 ID `8fa09bce`。
- `3ff3` 仍为 `ffff`，因此宏中的位移仍按 [WRITES.md](WRITES.md) 的机制被跳过。
- `2400`、`2600` 至 `3cff`、`3e00` 现为官方程序写入的保存表，校验通过，
  驱动可以完整解析 7 个配置。

## 实机写入测试

同日按 [WRITES.md](WRITES.md) 的流程，在上述只读备份之后测试：

1. 亮度 3 改为 2，读回为 2，用户确认灯变暗；再改回 3。
2. 用 `--save-dpi factory 1` 原样重新保存灵敏度表（擦写 `2400` 页），
   随后命令 `0d` 即时应用，运行参数读回一致。
3. 重新读取整片闪存，与测试前的备份逐字节相同。用户确认指针和按键正常。

4. 官方程序在按键区写入了灯效列表：头部第 13 字指向五组 (偏移, 0)，
   每组向量为两个零字加 `a4a4`，校验和覆盖到列表末尾。构建器原先不生成这一段。
   现在 `Configuration::lighting` 原样保留这些向量，离线重建与官方写入的 633 字逐字相同。
5. 用 `--save-buttons` 原样重新保存按键区，读回一致；整片闪存与测试前逐字节相同。
   用户确认各按键、滚轮和滚轮灯正常。

## RGB 魔幻灯效

官方「灯光亮度」页（`TtabBrightness`，`006f161c`）的「RGB魔幻灯效」下拉框按语言文件顺序加入
`ColorEffect1` 至 `ColorEffect7`，改变时把选中序号存入全局变量并向主窗口发送消息 `0x45b`。

2026-10-21 用 usbmon 被动记录官方程序在虚拟机中的 USB 流量。每次改变选项，官方程序：

1. 读取命令 `05`，按 [SAVING.md](SAVING.md) 的流程重写整个按键表。
   与之前的表相比，只有 7 个配置元数据的第 0 字高字节和两个校验字改变。
2. 发送 `0e`（读取后以写标志 `80` 写入 `64 64 64 64`）、`0f`（`07`）和 `0c`
   （配置数量、`80 | 当前配置`、按键响应时间），即重新载入当前配置。

`0e` 写 RAM `30`、`32` 至 `34`、`36` 至 `3b`，`0f` 写 RAM `2b` 并置位 `3e.7`，`0c` 写 RAM `264`、`262`、`25`。
实机测试只用保存按键表加 `0c` 重新载入（驱动的 `select_profile`），灯效即时生效：
灯效 0 常亮、灯效 3 多色慢循环，闪存只改变上述 9 个字，用户确认按键和指针正常。
`0e` 和 `0f` 的含义未确认，驱动不发送。
